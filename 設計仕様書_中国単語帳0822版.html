1. 概要

項目 内容
種別 単一ファイル完結型の Web アプリ（SPA）
用途 中国語単語帳。FSRS-5 による間隔反復学習
ファイルサイズ 約 434 KB（うち語彙データが約 350 KB）
総行数 1,685 行
収録語数 2,568 語（初期データ）
外部依存 ゼロ。CDN・フォント・API 呼び出しを一切行わない
ビルド 不要。ファイルをブラウザで開けば動作する
対象環境 iOS Safari を主眼に置いたモバイル最適化。Claude のプレビュー内でも動作
言語 UI は日本語、学習対象は中国語（簡体字）

設計思想

  1. 1 ファイルで完結する — 配布・バックアップ・移行が「ファイルを 1 つコピーする」だけで済む。
  2. オフラインで完全に動く — ネットワークを一切必要としない。
  3. AI 連携はコピー＆ペーストで行う — アプリから API を叩かない。プロンプトを生成してユーザーに渡し、返ってきた JSON を貼り戻してもらう。API キーも通信も不要。
  4. データを失わないことを最優先する — 保存の多重リトライ、退避コピー、CSV 書き出しを用意している。

3. データモデル

3.1 CARDS — カードの実体（配列）

{ id: 1, zh: "你把剪刀还给对方时…", py: "nǐ bǎ jiǎn dāo…", m: "ハサミを相手に返すときは…", n: "" }
キー 型 意味
id number | string 一意識別子。初期データは 1〜2779 の飛び番あり整数。ユーザー追加分は "u" + タイムスタンプの文字列
zh string 中国語（簡体字）。検索・CSV 突合のキーとして使われる実質的な自然キー
py string 声調記号付きピンイン
m string 日本語の意味
n string 例文・備考。" ／ " 区切りで複数項目。「中国語｜日本語」形式と【注意】…形式を解釈する

初期データ 2,568 語のうち n（例文・備考）が入っているのは 418 語、py は全語に存在。

重要: id の型が number と string で混在するため、比較は必ず String(a)===String(b) で行っている。この規約はコード全体で守ること。

3.2 S — 学習状態（オブジェクト、id → 状態）

S[id] = { st, step, D, S, due, last, reps, lapses }
キー 型 意味
st 0-3 状態。0 = 未着手 / 1 = 学習中 / 2 = 復習 / 3 = 再学習
step number 学習ステップの現在位置（LEARN_STEPS の添字）
D 1-10 FSRS の難易度（Difficulty）
S number FSRS の安定度（Stability、単位=日）。0.1〜36500 にクランプ
due number 次回出題時刻（epoch ミリ秒）
last number 前回採点時刻（epoch ミリ秒）。経過日数の計算に使う
reps number 通算採点回数
lapses number 復習状態から「もう一度」で落ちた回数

S にエントリが無いカード＝未着手。getSt(id) が初回アクセス時に初期値を生成する。2,568 語すべてに最初からエントリを作る設計にはしていない（保存サイズを抑えるため）。

3.3 CFG — 設定

キー 既定値 取りうる値 意味
retention 0.9 0.8 / 0.85 / 0.9 / 0.95 目標記憶率。高いほど復習間隔が短い
newPerDay 20 0-200 1 日の新規カード上限
dir 'zh' zh / jp 出題方向（表面の言語）
order 'seq' seq / rand 新規カードの出題順
sessionMax 0 0-500 1 セッションの出題上限（0 = 無制限）
bias 'review' new / review / mix 出題傾向
reviewEvery 0 0-50 N 問ごとに復習を挟む（0 = 無効）
browseSort 'seq' seq / seqd / mlow / mhigh 一覧画面の表示順（2026-08 追加）

3.4 LOG — 日次記録

キー 意味
date 集計対象日（YYYY-MM-DD）。日付が変われば newDone/revDone をリセット
newDone その日にこなした新規カード数（新規上限の消化量）
revDone その日の復習回数
streakDays 連続学習日数
lastStudy 最後に学習した日（連続判定用）

3.5 UC / OV / DL — 初期データへの差分

初期データ CARDS はソースコード上のリテラルであり書き換えられない。そこで差分方式を採っている。

変数 型 役割
UC 配列 ユーザーが追加したカード。読み込み時に CARDS に push
OV オブジェクト 既存カードへの修正内容（id → {zh,py,m,n}）。読み込み時に上書き適用
DL 配列 削除された既存カードの id（トゥームストーン）。読み込み時に CARDS から除去

適用順は applyLoadedPayload() 内で UC 追加 → OV 上書き → DL 除去 の順（388-396 行）。

3.6 RL — 復習履歴（revlog）

RL = [ [cardId, 採点時刻(秒), 評価1-4, 前回からの経過日数, 採点前のst], ... ]

配列の配列でサイズを切り詰めている。上限 RL_MAX = 50000 件、超過分は古い順に破棄。本体データとは別キーに保存され、履歴の保存に失敗しても学習状況の保存は妨げない（意図的な分離）。書き出し専用で、読み込みには対応していない。

4. 永続化

4.1 保存先の抽象化

storageGet(key) / storageSet(key, value)
  ├─ window.storage が存在する場合 → Claude の会話ストレージ（storageKind='claude'）
  ├─ localStorage が使える場合     → 端末のブラウザ内（storageKind='local'）
  └─ どちらも不可                   → セッション内メモリのみ（storageKind='none'）

detectStorageKind()（379-386 行）が起動時に判定する。none の場合はホーム画面に警告バナーを出し、ページを閉じると進捗が消える旨を伝える。

4.2 保存キー

キー 内容
hsk-fsrs-v1 本体。{s, cfg, log, uc, ov, dl} を JSON 化したもの
hsk-fsrs-v1-revlog 復習履歴（RL の JSON）
hsk-fsrs-v1-backup 常に localStorage に置かれる退避コピー。Claude 側の保存が失敗しても端末側に最新スナップショットが残る

4.3 保存フロー

変更発生
  └→ scheduleSave()          … dirty=true、600ms のデバウンス
       └→ saveState()
            ├─ saveInFlight があれば待つ（並行書き込みを直列化）
            ├─ storageSet を最大 4 回試行（間隔 500 / 1,200 / 2,500 ms）
            ├─ 成功 → dirty=false、safetyBackup() で退避コピー更新
            └─ 失敗 → showErr（赤帯）+ showPending（再試行ボタン付き通知）
                     + ensureBgRetry（8 秒間隔でバックグラウンド再試行）

補助的に visibilitychange（ページが隠れたとき）と学習完了時にも saveState() / saveRL() を呼んでフラッシュしている。

4.4 起動時の復元

loadState()
  ├─ storageGet('hsk-fsrs-v1') 成功 → applyLoadedPayload()
  └─ 失敗 かつ storageKind==='claude'
       └→ localStorage の 'hsk-fsrs-v1-backup' を代わりに適用
            + dirty=true にして「未保存」扱いにし、自動再保存を開始

注意: applyLoadedPayload() は UC を CARDS に push する。この関数を 1 回の起動で 2 回呼ぶとカードが重複する。現状の呼び出し経路では二重呼び出しは起きないが、改修時はこの前提を壊さないこと。

4.5 後方互換性の担保方法

CFG = Object.assign(CFG, o.cfg || {});
LOG = Object.assign(LOG, o.log || {});

既定値を持つオブジェクトに保存値をマージする方式のため、保存データに存在しないキーは既定値のまま残る。新しい設定項目を足しても古い保存データがそのまま読める。

加えて、値の妥当性は使用側で検証する（browseSort() が未知の値を 'seq' に落とす形）。新しい設定を追加するときは「既定値の宣言」＋「使用側でのフォールバック」の 2 点をセットで実装すること。

5. FSRS-5 アルゴリズム

5.1 定数

W = [0.40255, 1.18385, 3.173, 15.69105, 7.1949, 0.5345, 1.4604, 0.0046,
     1.54575, 0.1192, 1.01925, 1.9395, 0.11, 0.29605, 2.2698, 0.2315,
     2.9898, 0.51655, 0.6621]          // FSRS-5 の既定パラメータ（19 個）
DECAY  = -0.5
FACTOR = 0.9^(1/DECAY) - 1 = 19/81
LEARN_STEPS   = [1, 10]   // 分。新規・学習中
RELEARN_STEPS = [10]      // 分。再学習

5.2 主要な式

関数 式 意味
retr(t, S) (1 + FACTOR·t/S)^DECAY 経過 t 日後の想起率 R
nextInterval(S, r) max(1, round(S/FACTOR · (r^(1/DECAY) − 1))) 目標記憶率 r を満たす次回間隔（日）
D0(g) clamp(W4 − e^(W5·(g−1)) + 1, 1, 10) 初回難易度
S0(g) max(W[g−1], 0.1) 初回安定度
nextD(D, g) clamp(W7·D0(4) + (1−W7)·(D + (−W6·(g−3))·(10−D)/9), 1, 10) 難易度の更新（平均への回帰つき）
recallS(D,S,R,g) clamp(S·(1 + e^W8·(11−D)·S^(−W9)·(e^(W10·(1−R))−1)·hard·easy), 0.1, 36500) 想起成功時の安定度更新。hard = W15 (g=2)、easy = W16 (g=4)
forgetS(D,S,R) clamp(min(W11·D^(−W12)·((S+1)^W13 − 1)·e^(W14·(1−R)), S), 0.1, 36500) 失敗時の安定度更新（必ず現在値以下）

5.3 状態遷移（rate(id, g)、572-608 行）

        ┌─────────── g=1 ───────────┐
        ↓                            │
   [0 未着手] ─ g=2 ─→ [1 学習中] ──┘
        │                  │
        │ g=4              │ g=3 で step++、step が LEARN_STEPS を超えたら卒業
        ↓                  ↓
     ┌──────────── [2 復習] ────────────┐
     │                 │                 │
     │            g=2/3/4                │ g=1 → lapses++、安定度を forgetS で減衰
     │      安定度を recallS で更新       ↓
     │      due = now + nextInterval  [3 再学習] ─ g=3 で 10 分後 → 卒業して [2 復習]
     └───────────────────────────────────┘
  • 採点は必ず logReview(id, g, c) を更新前に呼んで履歴に記録する。
  • LOG.newDone は「採点前が未着手だったカード」でのみ増える。
  • LOG.revDone は「採点後に復習状態」または「g=1」のときに増える。

5.4 同一セッション内の再出題

学習ステップ（1 分後・10 分後）のカードを同じセッション中に再び出す挙動は、CFG.bias === 'review' のときのみ有効（790 行）。他の出題傾向では再出題せず、期限が来た次回セッションに回す。

6. 出題キュー

buildQueue()（646-683 行）が毎回ゼロから組み立てる。

全カードを 3 群に分類
  due   … st=2 かつ 期限到来
  learn … st=1 または 3 かつ 期限到来
  fresh … 未着手（st=0 または S にエントリ無し）

① due / learn を「期限の古い順」にソート（ランダム設定でも期限切れを放置しない）
② fresh を CFG.order で並べ（seq=登録順 / rand=シャッフル）、
   newPerDay − LOG.newDone 枚まで切り出す
③ CFG.bias で連結
      new    : [新規] + [learn] + [due]
      review : [learn] + [due] + [新規]        ← 既定
      mix    : [learn] + shuffle([due] + [新規])
④ interleaveReview(q, CFG.reviewEvery) を適用（bias より優先）
⑤ CFG.sessionMax で先頭から切り詰め

interleaveReview の方式

N 問ごとの位置に復習カードが来ていなければ、後方にある復習カードをその位置へ前倒しする。カードを増やす（重複出題する）方式ではない。前倒しできる復習カードが尽きたら以降はスキップして終了する。

renderCard 側の補正（738-743 行）

キュー先頭が「学習中だが期限がまだ来ていない」カードだった場合、末尾へ回す。無限ループを避けるため guard でキュー長ぶんの回数に制限している。

並び替え (BSORTS, 815-820 行):

値 表示ラベル 挙動

7.4 追加（AI 連携フロー）

① 中国語を入力
     ↓ 重複チェック（CARDS 内に同じ zh があれば拒否）
② buildPrompt(zh) でプロンプトを生成 → ユーザーがコピーして Claude に送信
③ 返ってきた JSON を貼り付け → extractJSON() で解析
     ├ warn があれば警告表示
     └ py も m も空 → 実在しない語と判断して保存フォームを開かない
④ 内容を確認・修正して保存 → UC と CARDS に push、id = "u" + Date.now()

extractJSON() の三段構え（1081-1106 行）— スマホのコピペで壊れた JSON を救済する:

  1. コードフェンス（json ``）を除去して素直にJSON.parse`
  2. 失敗 → normalizeSmartQuotes() で構造上の全角引用符（“ ” „ ‟ ″ 〃 ＂）のみ半角化。文字列の中身にある引用符は壊さない
  3. 失敗 → firstObject() で波括弧の対応を数え、最初の完全なオブジェクトだけを抽出して再試行

7.5 編集

  • 4 項目のフォーム + 「Claude で内容を更新する」プロンプト生成
  • 返ってきた JSON と現在値を項目ごとに並べて比較（renderDiff）
  • 各項目に「現在のまま / 置き換え / 追記」の 3 ボタン。既定は「置き換え」
  • 反映内容はテキストエリアで自由に手直しできる
  • review フィールドがあれば Claude からの指摘として表示
  • 削除ボタン（confirm で確認）

編集の保存先は applyEdit() が振り分ける: ユーザー追加カードなら UC を、既存カードなら OV を更新する。

8. CSV 入出力

8.1 カード CSV

列（CSV_COLS）:

中国語, ピンイン, 日本語の意味, 例文・備考, 状態, 復習予定日, 安定度, 難易度, 復習回数, 間違えた回数
  • 文字コード: BOM 付き UTF-8（Excel の文字化け対策）、改行 CRLF
  • ファイル名: <このHTMLのファイル名>_<YYYYMMDDhhmmss>.csv
  • 「状態」は日本語ラベル（ST_NAME / ST_CODE で相互変換）
  • 「復習予定日」は ISO 8601 文字列

読み込み:

  • 中国語 と 日本語の意味 列は必須。無ければ形式エラー
  • zh が一致するカードがあれば上書き、無ければ追加（id = "u" + Date.now() + "_" + 行番号）
  • 「学習進捗も一緒に取り込む」チェックが有効で、状態が未着手以外なら S[id] を再構築
  • パーサ parseCSV() は RFC 4180 準拠（引用符・エスケープ・セル内改行に対応）

既知の欠落: エクスポートに step と last の列が無い。インポート時は step: 0、last: Date.now() で再構築されるため、往復させると学習ステップ位置と経過日数の起点が失われる。安定度・難易度・期限は保たれるので実用上の影響は限定的だが、厳密な移行を求めるなら列の追加が必要（→ ROADMAP.md）。

8.2 復習履歴 CSV

中国語, カードID, 復習日時, 評価, 経過日数, 復習前の状態

書き出し専用。将来の FSRS パラメータ最適化や学習分析のための素材として設計されている。

11. 既知の制約と注意点

改修時に踏みやすい落とし穴を挙げる。

  1. ピンイン検索が声調記号に非対応 — py は shì のように声調記号付きで格納されているため、shi で検索してもヒットしない。
  2. 検索がインクリメンタルかつ無デバウンス — 1 文字入力ごとに 2,568 件を filter し、innerHTML を再構築する。現状の件数では体感できる遅延は無いが、語数が増えれば効いてくる。
  3. 削除はトゥームストーン方式 — 既存カードを削除すると DL に id が残る。同じ語を CSV から再インポートすると、zh 一致検索は CARDS から除去済みのため引っかからず、新しい u... カードとして復活する（重複はしないが id が変わる）。
  4. applyLoadedPayload() の二重呼び出し禁止 — UC を CARDS に push するため、2 回呼ぶとカードが重複する。
  5. esc() はシングルクォートを変換しない — 現状 HTML 属性はすべてダブルクォートで囲まれているため実害は無いが、属性をシングルクォートで書く改修をすると壊れる。
  6. LOG.revDone の計上条件 — else if (c.st === 2 || g === 1)。学習中カードに「普通」を付けて卒業しなかった場合はカウントされない。仕様として意図的か要確認。
  7. storageKind === 'claude' は会話スコープ — Claude のプレビュー内で使う場合、別の会話ではデータを引き継げない。移行手段は CSV 書き出しのみ。
  8. 保存サイズ — 本体 JSON は S が全カードぶん埋まると約 250 KB。RL は上限 5 万件で 1.5〜2 MB 程度。localStorage の 5 MB 制限には収まるが、余裕は大きくない。
  9. sessionTotal のずれ — 学習中に削除したり、renderCard がキューを並べ替えたりすると、進捗バーの分母が実際の残数と一致しないことがある。
  10. 語彙データがソースコード直書き — 350 KB のリテラルを毎回パースする。起動は十分速いが、語数を大幅に増やすなら構造の見直しが必要（→ ROADMAP.md）。

12. 改修時のチェックリスト

新しい機能を足すとき、以下を確認すること。

  • CFG に設定を追加した場合、既定値の宣言と使用側でのフォールバックの両方を書いたか
  • 保存データの形（{s, cfg, log, uc, ov, dl}）を変えていないか。変えるなら旧形式を読める経路を残したか
  • id の比較を String() 経由で行っているか
  • ユーザー入力を画面に出すとき esc() を通しているか
  • 新しい画面を足したら setNav() の配列と $('#nav-*') の束縛を更新したか
  • CSV の列を増やした場合、列が無い古い CSV も読めるようにしたか（ix(name) が -1 を返す前提で書く）
  • <script> ① の行数を変えていないか（変えるとエラー行番号の目安がずれる）
  • iPhone の実機幅（320px / 390px）でレイアウトが崩れないか

使い方と困ったときの対処

FSRS-5 を使った中国語単語帳アプリの使い方です。

1. はじめに

これは何か

中国語の単語カード（フラッシュカード）アプリです。FSRS-5 という間隔反復アルゴリズムが、カードごとに「そろそろ忘れそうな頃合い」を計算して復習日を決めます。闇雲に繰り返すより少ない回数で長く覚えていられます。

  • 収録語数: 2,568 語（自分で追加もできます）
  • HTML ファイル 1 つで動きます。インストール不要、ネット接続も不要
  • 進捗は自動保存されます

開き方

環境 手順
iPhone / iPad（推奨） ファイルアプリでプレビューするのではなく、共有ボタン →「Safariで開く」 を選んでください。プレビュー表示では保存が効きません
Claude アプリ内 プレビューをそのまま使えます。ただし進捗はその会話の中だけで保持されます（後述）
パソコン ファイルをダブルクリック、またはブラウザにドラッグ＆ドロップ
Documents by Readdle など 内蔵ブラウザで開けば動きます

表示 意味

4. 一覧で探す・並べ替える

4.1 検索

検索窓に入力すると、中国語・ピンイン・日本語の意味・例文 のすべてから部分一致で探します。

ピンインは声調記号つき（shì など）で登録されています。声調記号なしの shi では見つかりません。中国語か日本語で探すのが確実です。

4.2 並び替え

検索窓の右のセレクトで表示順を変えられます。選んだ順番は保存され、次に開いたときも維持されます。

選択肢 並び
登録が古い順 最初から入っている順（既定）
登録が新しい順 最近追加した語が先頭に来ます。自分で足した語を確認するときに便利
習熟度が低い順 未着手 → 再学習 → 学習中 → 復習（記憶の定着が浅い順）。苦手な語を洗い出すのに使います

習熟度は、そのカードの学習状態と FSRS の「安定度」（記憶が何日もつかの推定値）から計算しています。同じ習熟度のカードは登録順を保つので、並びが毎回変わることはありません。

  • 中国語・ピンイン・意味・例文

5. 語句を追加する

このアプリはインターネットに接続しません。代わりに、Claude に聞くための文章を用意して、その返事を貼り戻す方式を採っています。

手順

① 中国語を入力する

「追加」タブで覚えたい語句を入力し、「Claudeへ送る文を作る」を押します。すでに登録済みの語句は弾かれます。

② 文をコピーして Claude に送る

生成された文章を「この文をコピー」でコピーし、Claude との会話に貼り付けて送信します。

③ 返ってきた JSON を貼り付ける

Claude の返事（{ } で囲まれた部分を含む全体）をコピーして、貼り付け欄に入れ「返答を反映する」を押します。

コードブロックの記号や、スマホのコピペで混ざる全角の引用符（“ ”）は自動で処理されます。返事の全体をそのまま貼って構いません。

④ 内容を確認して保存する

ピンイン・意味・例文が自動で入るので、必要なら手直しして「カードを保存」。

誤入力のチェック

Claude が「その語は存在しない／一般的でない」と判断した場合、⚠️ 警告が表示され、保存フォームは開きません。聞き間違いや打ち間違いをそのまま登録してしまうのを防ぐ仕組みです。

Claude が返してくれる内容

  • 声調記号付きピンイン（文の場合は前後関係から多音字を判断、単体語は読み分けを併記）
  • 日本語訳
  • 日常会話で実際に使われる自然な例文 2 つ
  • 使用上の注意点（目上には使わない、ネット用語、地域差など）

6. 既存のカードを直す

一覧 → カードをタップ → 「編集・削除」で編集画面に入ります。

手で直す

4 つの欄を書き換えて「修正を保存」。

Claude に精査してもらう

「Claudeへ送る文を作る」を押すと、現在の登録内容を含んだプロンプトが生成されます。Claude に送り、返ってきた JSON を貼って「比較する」を押すと、項目ごとに現在の内容と提案が並びます。

各項目について 3 つから選べます。

選択 動作
現在のまま 変更しない
置き換え（既定） Claude の提案で上書き
追記 現在の内容の後ろに ／ で繋げて追加

反映される内容はテキストエリアで自由に手直しできます。納得したら「この内容でカードを更新」。

Claude が現在の登録内容の誤りを指摘した場合は、⚠️ として上部に表示されます。

削除

編集画面の下部「このカードを削除」。確認ダイアログが出ます。そのカードの学習履歴も一緒に消えます。

8. バックアップと移行

8.1 なぜバックアップが要るか

進捗はブラウザの中（または Claude の会話の中）に保存されています。以下の場合に失われます。

  • ブラウザのデータを消したとき
  • 別の端末・別のブラウザで開いたとき
  • Claude で使っている場合、別の会話に移ったとき
  • HTML ファイル自体を新しい版に差し替えたとき

定期的な CSV 書き出しを強く推奨します。

8.2 CSV を書き出す

設定 →「CSVファイルをダウンロード」。全カードが学習進捗つきで保存されます。

  • ファイル名は <HTMLのファイル名>_<日時>.csv
  • Excel / Google スプレッドシートでそのまま開けます（文字化けしません）

8.3 CSV を読み込む

設定 →「CSVを読み込む」でファイルを選び、「選んだCSVを取り込む」。

  • 中国語が一致するカードは上書き、無いものは追加されます
  • 「学習進捗も一緒に取り込む」のチェックを外すと、カードの内容だけを取り込みます

新しい版の HTML に乗り換える手順:

  1. 古い版で CSV を書き出す
  2. 新しい版の HTML を開く
  3. 設定 → CSV を読み込む（進捗込みで）

復習間隔・難易度・復習回数は引き継がれますが、「学習ステップの途中だったカード」の細かい位置と「最後に学習した日時」は引き継がれません。実用上は問題ない範囲ですが、厳密には一致しません。

8.4 復習履歴の書き出し

設定 →「復習履歴のCSVをダウンロード」。1 回ごとの採点記録（いつ・どのカードを・どう評価したか）が出力されます。学習の分析や、将来 FSRS のパラメータを自分用に最適化するための素材になります。読み込みには対応していません。

8.5 リセット

設定 →「学習進捗をすべてリセット」。S（各カードの学習状態）と復習履歴が消えます。カードそのもの（追加したカードや編集内容）は残ります。 取り消せません。

9. 困ったときは

症状 対処
「この環境では進捗を保存できません」と出る ブラウザのプライベートモードやストレージ無効設定が原因。通常モードの Safari / Chrome で開き直してください
画面上部に赤い帯が出た 保存失敗かプログラムエラーです。自動で再試行されます。その帯をスクリーンショットして相談すると原因を特定できます
下部に「まだ保存されていません」と出続ける 「今すぐ再試行」を押してください。それでも消えない場合は CSV を書き出して退避してください
進捗が消えた ①別の会話・別のブラウザで開いていないか確認 ②CSV のバックアップがあれば読み込む
JSON を読み取れませんと出る Claude の返事のうち { から } までを含む部分を、省略せずに貼り付けてください
ピンインで検索できない 声調記号なしでは一致しません。中国語か日本語で検索してください
画面が真っ白／JavaScript が必要と出る ファイルアプリのプレビューではなく、共有ボタンから「Safariで開く」を選んでください

改修・拡張提案

直すべき点と次に足すもの

現行版（Chinesewords_0822.html）を踏まえた、修正すべき点と拡張の候補です。 単一 HTML ファイル・外部依存ゼロ・オフライン動作 という設計上の制約を守ることを前提としています。

各項目には次の指標を付けています。

  • 効果: ★☆☆（限定的）〜 ★★★（体験が明確に変わる）
  • コスト: S（数十行）／ M（100〜300 行）／ L（構造変更を伴う）
  • 互換性リスク: 低 / 中 / 高

A. 先に直したい点（バグ・不整合）

A-1. ピンイン検索が声調記号に一致しない ★★★ / S / 低

py は shì ér bù jiàn のように声調記号つきで格納されているため、shi では検索できません。実用上いちばん困る欠陥です。

修正案 — 検索用に正規化した文字列を用意する:

// 声調記号を取り除く（NFD 正規化して結合用ダイアクリティカルマークを除去）
const deTone = s => (s||'').normalize('NFD').replace(/[̀-ͯ]/g,'').toLowerCase();

// カード読み込み後に一度だけ索引を作る（毎回の検索で正規化しない）
const PYX = new Map();          // id -> 正規化ピンイン
function buildSearchIndex(){
  PYX.clear();
  for(const c of CARDS) PYX.set(c.id, deTone(c.py));
}

// 検索条件に追加
const qn = deTone(q);
hit = CARDS.filter(c =>
  c.zh.includes(q) ||
  c.py.toLowerCase().includes(q) ||
  (PYX.get(c.id)||'').includes(qn) ||    // ← 追加
  c.m.includes(q) || c.n.includes(q));

索引は applyLoadedPayload() の後と、カード追加・編集・削除・CSV 取り込みの後に再構築します。

A-2. 検索が無デバウンス ★★☆ / S / 低

1 文字ごとに 2,568 件を走査し innerHTML を再構築しています。今は問題になりませんが、語数が 1 万を超えると入力が引っかかります。

let qTimer=null;
$('#q').oninput=()=>{ clearTimeout(qTimer); qTimer=setTimeout(()=>{bLimit=50;draw()},120); };

A-3. CSV の往復で step と last が失われる ★★☆ / S / 低

エクスポート列に step（学習ステップ位置）と last（前回採点時刻）がありません。インポート時は step: 0、last: Date.now() で再構築されるため、retr(t, S) の経過日数の起点がリセットされます。

修正案: 列を 2 つ追加する。読み込み側は ix('学習ステップ') が -1 を返す前提で書けば、列の無い古い CSV もそのまま読める（現行のインポート実装はすでにこの方式）。

const CSV_COLS=[...既存..., '学習ステップ', '前回学習日時'];
// import 側
step: parseInt(iStep>=0?row[iStep]:'0')||0,
last: (()=>{ const v=Date.parse(iLast>=0?row[iLast]:''); return isFinite(v)?v:Date.now(); })(),

A-4. 削除したカードを CSV から戻すと ID が変わる ★☆☆ / S / 中

既存カードを削除すると DL に id が残ります。同じ語を CSV から再インポートすると CARDS に無いため新規 u... カードとして追加され、元の id には戻りません。

修正案: インポート時、zh が DL に載っている削除済みカードと一致したら DL から取り除いて元の id で復活させる。復活の可否をユーザーに確認する UI を出すのが親切です。

A-5. LOG.revDone の計上条件 ★☆☆ / S / 低

if(isNew) LOG.newDone++; else if(c.st===2 || g===1) LOG.revDone++;

学習中カードに「普通」を付けて卒業しなかった場合、復習回数に数えられません。意図的ならコメントを添え、そうでなければ else LOG.revDone++ に変更します。

A-6. esc() がシングルクォートを変換しない ★☆☆ / S / 低

現状は全属性がダブルクォートなので実害はありませんが、防御として ' → &#39; を追加しておくと将来の改修で壊れません。

A-7. renderDiff の色がハードコード ★☆☆ / S / 低

#EDF5F0 #CFE3D8 が直書きされています。CSS 変数（--good 系）に寄せると、後述のダークモード対応が一箇所で済みます。

B. 費用対効果の高い機能追加

B-1. 一覧の状態フィルタ ★★★ / S / 低

並び替えに続く自然な拡張です。並び替えセレクトの隣に、もう 1 つセレクトを置きます。

[すべて / 未着手 / 学習中・再学習 / 復習 / 自分で追加した分]

B-2. 一覧項目に習熟度バーを表示 ★★☆ / S / 低

const pct = st && st.st===2 ? Math.min(100, Math.round(Math.log10(1+st.S)/Math.log10(1+365)*100)) : 0;

B-3. 削除の取り消し（Undo） ★★☆ / S / 低

削除は confirm のみで、押し間違えると学習履歴ごと消えます。削除直前の {card, state, 元のindex} を保持し、トーストに「元に戻す」ボタンを出すだけで安心感が大きく変わります。

B-4. キーボードショートカット ★★☆ / S / 低

パソコンで使う場合、Space で答えを表示、1〜4 で採点できると速度が段違いです。

B-5. 発音の読み上げ ★★★ / S / 低

Web Speech API はブラウザ内蔵で、外部依存になりません。

function speak(zh){
  try{
    const u=new SpeechSynthesisUtterance(zh);
    u.lang='zh-CN'; u.rate=0.9;
    speechSynthesis.speak(u);
  }catch(e){}

カード裏面と詳細モーダルに 🔊 ボタンを置きます。中国語学習アプリとして効果が非常に大きい割に実装は最小です。ただし端末に中国語音声が入っていないと無音になるため、speechSynthesis.getVoices() で zh 系の有無を確認し、無ければボタンを隠す配慮が要ります。

B-6. JSON 一括エクスポート／インポート ★★★ / S / 低

現在の移行手段は CSV のみで、CFG LOG RL OV DL が引き継げません。保存しているペイロードをそのままファイルにするだけなので実装は数十行です。

function exportAll(){
  const payload={v:2, s:S, cfg:CFG, log:LOG, uc:UC, ov:OV, dl:DL, rl:RL};
  downloadBlob(new Blob([JSON.stringify(payload)],{type:'application/json'}),
               baseName()+'_full_'+stampNow()+'.json');
}

インポート側は v を見て分岐し、v が無ければ現行形式として読みます。会話をまたぐ移行・端末間の移行がこれで完全になります。 優先度は高めです。

B-7. 統計画面 ★★☆ / M / 低

C. 構造の見直し（再設計するなら）

C-1. 語彙データとコードの分離 ★★☆ / L / 中

現状は 358 KB の配列リテラルを起動のたびにパースしています。2,568 語なら問題ありませんが、1 万語規模にすると起動が目に見えて遅くなり、ファイルの編集も困難になります。

選択肢:

方式 利点 欠点
現状維持（インラインリテラル） 単一ファイルを維持できる 大規模化に弱い
<script type="application/json"> に格納 パース時期を制御できる。エディタが軽くなる 単一ファイルは維持、効果は限定的
IndexedDB に初回投入 大規模化に強い、部分読み込み可 初回起動が複雑に。単一ファイル性は保てる
別 JSON ファイル + fetch 編集が容易 file:// では CORS で読めない。単一ファイル原則に反する

推奨: 語数が 5,000 を超えるまでは現状維持。超えるなら IndexedDB。

C-2. 状態管理の一元化 ★★☆ / L / 中

現在、S CFG LOG UC OV DL RL が独立したグローバル変数で、保存時に手作業で組み立てています。1 つの store オブジェクトに束ね、store.mutate(fn) を通してのみ変更する形にすると、保存漏れ（dirty の立て忘れ）を構造的に防げます。

C-3. スキーマバージョンの導入 ★★★ / S / 低

これは早めにやっておくべきです。 現在、保存ペイロードにバージョン番号がありません。将来データ構造を変えるとき、旧形式か新形式かを判別する手掛かりが無くなります。

const SCHEMA=2;
// save
const payload=JSON.stringify({v:SCHEMA, s:S, cfg:CFG, log:LOG, uc:UC, ov:OV, dl:DL});
// load
function migrate(o){
  const v=o.v||1;              // v が無ければ現行形式（=1）とみなす
  if(v<2){ /* v1 → v2 の変換をここに書く */ }
  return o;
}

v が無い既存データを 1 として扱えば、今のデータを一切壊さずにバージョン管理を始められます。

C-4. 描画の差分化 ★☆☆ / L / 中

main.innerHTML の全置換は、画面数が少ない今は妥当な選択です（コードが単純で、状態の取りこぼしが起きない）。ただし一覧のスクロール位置が並び替えのたびにリセットされるなど、細かい不便があります。

優先度は低め。 やるなら一覧リストだけを部分更新する程度に留めるのが費用対効果に見合います。

C-5. FSRS 部分のテスト ★★☆ / M / 低

D0 S0 retr nextInterval nextD recallS forgetS rate はすべて純粋関数（rate は S に依存するが分離可能）です。この部分だけを別ファイルに切り出せば Node でユニットテストできます。

tests/fsrs.test.js
  - 既知の入力に対する出力の回帰テスト
  - 状態遷移の網羅（0→1→2、2→3→2 など）
  - nextInterval が retention に対して単調減少すること

アルゴリズムを触るときの安全網として価値があります。

C-6. PWA 化 ★★☆ / M / 中

Service Worker と manifest を追加すればホーム画面に追加でき、アプリらしく起動できます。

ただし file:// では Service Worker が動きません。 HTTPS 配信が前提になるため、「単一ファイルをどこにでも置ける」という現在の強みを一部手放すことになります。採用は配布方法の方針とセットで判断してください。

D. FSRS の精度向上

D-1. パラメータの個人最適化 ★★★ / L / 中

現在の W（19 個）は FSRS-5 の汎用既定値です。RL に採点履歴が蓄積されているので、これを使って自分専用に最適化できます。

現実的な進め方:

  1. 設定から復習履歴 CSV を書き出す（実装済み）
  2. 外部の fsrs-optimizer（Python）などに掛けて最適化した W を得る
  3. 設定画面に「FSRS パラメータ」の入力欄を設け、19 個の数値を貼り付けられるようにする（未実装／実装コストは小）

CFG.w（配列、未設定なら既定値）として保存すれば互換性の問題もありません。手順 3 だけ実装すれば、残りは既存の書き出し機能で完結します。 費用対効果が非常に高い提案です。

D-2. 復習履歴の取り込み対応 ★☆☆ / M / 中

現在 RL は書き出し専用です。B-6 の JSON 一括エクスポートを実装すれば履歴も含めて移行できるため、CSV での取り込みは不要になります。B-6 を優先すべきです。

D-3. 「もう一度」の扱いを設定可能に ★☆☆ / S / 低

現在、学習ステップでの同一セッション再出題は「復習優先」のときのみ有効という、やや発見しづらい仕様です（設定画面に注記あり）。出題傾向と切り離した独立の設定にするほうが素直です。

F. 実装するときの約束事

改修が現在の設計思想を壊さないよう、以下を守ってください。

  1. 外部依存を増やさない — CDN、Web フォント、外部 API を使わない。オフラインで完全に動くことがこのアプリの前提です。
  2. 単一ファイルを維持する — 分割したくなったら、まず「本当に必要か」を問う。
  3. 保存データの後方互換を必ず担保する — 新しいキーには既定値を用意し、使用側にフォールバックを置く。既存キーの意味は変えない。
  4. id の比較は String() 経由で — number と string が混在しています。
  5. ユーザー入力は esc() を通す — innerHTML を多用する構造のため必須です。
  6. 保存を伴う変更の後は scheduleSave() を呼ぶ — 呼び忘れると変更が消えます。
  7. iPhone の実機幅で確認する — 320px と 390px で崩れないこと。
  8. 改修後は必ず CSV を書き出して読み戻し、往復で壊れないことを確認する。
